## Rationale

Executor failed a discovery / identify-all fraud task at 53.9% (11 of 21 fraud payments recovered, 0 false positives). The Executor correctly enumerated multiple signal families and reached the impossible-travel signal that does flag the cohort, but then narrowed the answer to one customer's 11-record burst and discarded smaller impossible-travel sub-clusters belonging to three other customers in the same archive window. The discard reasoning was explicit in the executor log: 'PMF overlap: set(), DFP overlap: set()' between the headline burst and the smaller sub-clusters, plus the headline burst had unique fingerprints not appearing anywhere else. v0007's rules 4-6 supplied the justification for the narrowing: rule 4 says a cohort 'shares at least one exact identifier', rule 6 says 'one hit' implies 'sharing one or more discrete identifiers (a fingerprint, a customer, a status-invariant violation)' and warns that a candidate set 'spanning many unrelated customers' is noise. Read literally, those rules tell the Executor to keep only the largest internally-coherent sub-cluster of a signal and to drop other sub-clusters that lack a shared fingerprint — which under-counts any multi-actor fraud campaign / quality cohort where several accounts independently run the same playbook. Also contributing: the Executor used LIMIT 20 on the impossible-travel query, capping visibility into sibling sub-clusters. Fix is surgical: (a) extend rule 4 to clarify 'discrete shared property' explicitly includes the structural condition the signal tests (being-paired-by-impossible-travel) and that disjoint sub-clusters all matching the same structural condition stay together as one cohort; (b) extend rule 5 with a 'cohort-wide application' paragraph: when one signal returns several disjoint sub-clusters in the brief's scope, every record in every sub-cluster goes in — drop a sub-cluster only when the brief's explicit scope excludes it (one specific store/day/actor); (c) rewrite rule 6 so 'one hit' is explicitly compatible with multiple actors running the same MO inside the brief's scope window, and the internal-coherence test becomes 'same structural signal in the same scope window' rather than 'shared fingerprint across every record'; (d) extend rule 7 (coverage check) to require recording sub-cluster counts per discrete signal and to require running the cohort query without LIMIT; (e) add two anti-patterns: ranking-sub-clusters-and-keeping-the-strongest, and using LIMIT on the discovery query; (f) reword the existing 'one hit reads as count' anti-pattern to also warn against reading it as a single-actor / single-fingerprint constraint. Pulls the rule away from the prior 'too narrow' failure mode without dropping any v0006/v0007 precision guardrails — the discrete-identifier-over-threshold rule still holds, and a noisy threshold sweep still does not become acceptable; what changes is that a discrete-identifier signal returning multiple disjoint sub-clusters now uses the union rather than the largest sub-cluster.

## Rollback

Create a new version from v0007 content if the new 'disjoint sub-clusters all stay in' rule causes the Executor to over-report cohorts on tasks where the brief did mean to scope to a single actor / cluster (e.g. the grader flags an answer that swept in unrelated sub-clusters from a signal that happened to fire on the noise too); the narrower revert is to drop the 'Cohort-wide application' paragraph from rule 5 and the rewritten rule 6 wording while keeping the rule-7 sub-cluster-count requirement and the no-LIMIT discipline.
